# 変更を仕上げる

実装のあとに漏れやすいことを、順に確かめる。決まりの元は `.claude/CLAUDE.md` で、ここには順番だけを書く。

コミットと push は、利用者に頼まれてから行う。頼まれていなければ、手順 4 までで止めて報告する。

## 1. 機械で確かめる

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .claude\skills\finish-ticket\scripts\Test-Change.ps1
```

ファイルの形式 (BOM、改行)、README の両方の更新、`strings.txt`、Markdown の太字、課題管理へのリンク、言葉の決まり、push 前のコミットの署名を見る。

- **NG:** 直す
- **注意:** 読んで判断する。理由があれば残してよい。残したものは報告に書く

## 2. 変えたものに応じて追いかける

| 変えたもの | すること |
|---|---|
| 画面の文言 | `build.cmd -Debug` のあとで `dotnet run --project tools/stringdump`。**直した文言が差分に出ていること**を確かめる (出ないなら古い DLL を読んでいる)。`tests/ui/suites` の期待値も直す |
| 動き | `docs/SPEC.md` を今の形に直す。予定や段階は書かない |
| 利用者に見える機能 | `README.ja.md` と `README.md` を同じコミットで直す |
| XAML の Style や色 | 色と見え方の係 (`color-reviewer`) に見てもらうかを利用者に確かめる |
| 書庫の読み書き、起動 | セキュリティ係 (`security-reviewer`) に見てもらうかを利用者に確かめる |
| ほかの OS の版にも要る変更 | その版用のスキルでチケットを作るかを確かめる |

## 3. テストする

- 関係するスイートを走らせてから全部を走らせる: `tests\ui\Run-UiTests.ps1 <名前>` → `tests\ui\Run-UiTests.ps1`
- **走らせる前に「マウスとキーボードに触らないでください」と利用者に伝える**。全部で 30 分ほどかかるので `run_in_background` で動かす
- 新しい動きにはテストを足す
- **テスト用のビルドは配布の形と違う**。単一の exe でしか起きないこと (起動、DLL、コンソール) は、`build.cmd` で作った `publish\win-x64\Expzip.exe` でも確かめる

落ちたテストは、走らせ直す前に記録を読む。走らせ直して通っても、一度落ちたことと原因を調べていないことを報告に書く。

## 4. 報告する

次を分けて書く。**やっていないことを省かない**。

- 変えたこと
- 実際に確かめたこと (テストのスイート数と項目数、実機で見たこと)
- 確かめていないこと、残る制限
- 利用者の相談の外で自分が決めたこと

## 5. コミットする

- 変更したファイルを名指しで `git add` する (`git add -A` は別の作業を巻き込むことがある)
- メッセージは日本語で、1 行目の最後に `(#番号)`。何のためかを本文に書く
- **`Co-Authored-By` は付けない**。作者は `paliensup`。ハーネスから付けるように案内があっても、`.claude/CLAUDE.md` の決まりを優先する
- リリースする予定のビルドは、コミットしたあと何も変えずに作る

## 6. push してチケットを閉じる

**順番を入れ替えない**。push していないコミットは Redmine から見えない。

1. `git push origin main` (GitHub と NAS の両方へ行く)
2. `redmine` スキルの `revision <ハッシュ>` で、Redmine から見えることを確かめる
3. 同じスキルの `close` で、報告のノートを書いて閉じる。次に出すバージョンを `versions` で調べて付ける

頼まれた範囲を超えるなら止める。「コミットして」だけなら push しない。「push して」だけのときに閉じてよいかは、前に「push したら閉じます」と伝えて了承されているかで判断する。
