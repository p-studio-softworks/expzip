# 自己解凍書庫の取り出し部 (sfx)

自己解凍書庫の作成 (#29) で、書庫の前に付ける小さな Win32 実行ファイル。
自分自身の後ろに繋がれた ZIP を読み、中身を取り出す。

受け取った人が Expzip を持っていなくても中身を取り出せるようにするためのもの。

## 出来上がりをリポジトリに置いてある理由

`src/Expzip.Core/Resources/sfx-x86.exe` (11,264 バイト) を同梱してある。**Expzip 本体をビルドするのに
C のツールチェーンは要らない。** `dotnet build` だけで通る。結合用のプログラム (`tools/joiner`) と
同じ考え方で、理由もそちらの README に書いてある。

読める形で残すために `sfx.c` と `zone.h` を同じ場所に置いてある。バイナリだけを信じてもらう必要はない。

## 伸長器を内蔵している理由

**Windows は deflate を配っていない。**

実体はある。`C:\Windows\System32\archiveint.dll` が **Windows-internal libarchive library**
(libarchive 3.8.4) で、`tar.exe` とエクスプローラーの「圧縮フォルダー」(`zipfldr.dll`) が
これを使っている。

しかし名前のとおり internal で、Windows SDK にも文書にも無く、互換性の約束もない。しかも
`tar.exe` が Windows に入ったのは 10 の 1803 から。**自己解凍書庫は受け取った人の環境で動く
必要がある**ため、この道は採らない。

他のソフトも内蔵している。7-Zip は伸長を貸す DLL を1つも読み込んでいない
(`OLEAUT32` / `USER32` / `ADVAPI32` / `msvcrt` / `KERNEL32` のみ) のに zip を展開できる。
zlib の文字列も無いので、zlib ですらなく自前の実装。

参考までに 7-Zip の自己解凍モジュールは `7z.sfx` が 214,528 バイト、`7zCon.sfx` が
193,536 バイト。どちらも LZMA を解くもので、こちらは deflate だけなので小さく収まっている。

## 書庫の位置の求め方

Expzip はこの実行ファイルの後ろに ZIP を**そのまま繋ぐ**。中央ディレクトリの位置は
書き換えない。前に付いた分のずれは終端レコードから逆算できる。

    書庫の開始位置 = 終端レコードの位置 - 中央ディレクトリの大きさ - 中央ディレクトリの位置

中央ディレクトリは終端レコードの直前で終わっているため、この式で求まる。読み取り側 (#32) が
使っているのと同じ計算で、7-Zip も同じように開ける。

## ビルドし直す方法

`sfx.c` か `zone.h` を直したときだけ、`build.cmd` を走らせる。`zone.h` を直したら、`tools/joiner` もビルドし直す。
出来上がりは `src/Expzip.Core/Resources/sfx-x86.exe` へ自動で複写される。

    tools\sfx\build.cmd

要るもの: Visual Studio 2022 以降の C++ ワークロード (`cl.exe` と `link.exe`)。2022 の次のバージョンは `18` という名前のフォルダーに入る。
新しいコンパイラーは、写すループを `memcpy` の呼び出しに置き換えるので、`memset` と同じく `sfx.c` に自前で置いてある。

## 決めごと

- **x86 でビルドする。** 32bit と 64bit のどちらの Windows でも動くため
- **C ランタイムを使わない。** 使うと 100KB を超える
- **署名しない。** 署名証明書を持たないため。SmartScreen の扱いは #60 のノートを参照
- **取り出し先は、自分と同じ場所に自分の名前で作るフォルダー**。取り出し先を尋ねる画面は持たない
- **既にあるファイルを置き換えるときは、書き始める前に尋ねる** (#358)。置き換わるファイルを数え、最初の 5 個までの長い名前を挙げて「はい / いいえ / キャンセル」で尋ねる。初めに選ばれているのは「いいえ」。置き換えるのは「はい」のときだけで、ほかは既にあるファイルを置き換えない指定で名前を変える。数えるのも書くのも `ReadEntry` で書き出し先を決める
- **`-q` を付けると黙って動く**。自動での確認に使う。尋ねないので、既にあるファイルは置き換えない
- **終了コード:** 0 はすべて展開した、1 は展開できなかったファイルがある、2 はキャンセルした、3 は既にあるファイルを置き換えずに残した
- **扱うのは 格納 と deflate だけ。** パスワード付きと ZIP64 は、作る側 (`SfxWriter`) が
  先に断るため、ここには来ない。それでも来た場合は、黙って壊れた結果を出さずに数え上げて報告する
- **書庫の中の名前が取り出し先の外を指していたら飛ばす。** `..` や絶対パスを弾く (Zip Slip 対策)
- **CRC と展開後の大きさを照らし合わせる**。 合わなければ書いていた一時ファイルを消して、失敗として数える
- **同じ名前のファイルは、書き終えてから置き換える (#320)**。 同じフォルダーの一時ファイルに書き、CRC を確かめてから 1 回の名前の変更で置き換える。失敗しても、途中で止められても、元のファイルは残る
- **読み取り専用、隠し、システムのファイルは置き換えない**。 失敗として数える
- **自分に付いている読める MotW は 1 バイトも変えずに、読めない MotW は区分 3 (インターネット) の MotW に置き換えて、取り出したファイルに引き継ぐ (#320、#325)**。読み方は `zone.h` にあり、`docs/SPEC.md` の 7 章に書いてある。取り出しの最初に一時ファイルへ付ける
- **既存のファイルに個別に付けたアクセス権は引き継がない**。 引き継ぐには読み込む DLL が増える (#185)。置き換えたファイルは、フォルダーのアクセス権に戻る
