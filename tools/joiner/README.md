# 連結プログラム (joiner)

ファイルの分割 (#59) で、断片といっしょに書き出す小さな Win32 実行ファイル。
`.001` `.002` … を順につないで元のファイルに戻し、CRC で中身を確かめる。

受け取った人が Expzip を持っていなくても元に戻せるように、独立した実行ファイルにしてある。

## 出来上がりをリポジトリに置いてある理由

`src/Expzip/Resources/joiner-x86.exe` (4,608 バイト) を同梱してある。**Expzip 本体をビルドするのに
C のツールチェーンは要らない。** `dotnet build` だけで通る。

バイナリをリポジトリに置くのは避けたいが、代わりの案はどれも高くついた (#60 で実測)。

| 案 | 出来上がり | ビルドするのに要るもの |
|---|---|---|
| **C / C ランタイム無し (採用)** | **4,608 バイト** | MSVC |
| .NET NativeAOT (x86) | 747,520 バイト | MSVC (ILCompiler が link.exe を呼ぶ) |
| .NET NativeAOT (x64) | 881,152 バイト | MSVC |
| PE を自前で組み立てる | 最小 | なし |

NativeAOT でも結局 MSVC が要るため、**「C を持ち込まない」という利点が無い**。そのうえ 160 倍大きい。
PE を自前で書き出す案は、壊れやすく保守できないため採らない。

読める形で残すために `join.c` を同じ場所に置いてある。バイナリだけを信じてもらう必要はない。

## ビルドし直す方法

`join.c` を直したときだけ、`build.cmd` を走らせる。
出来上がりは `src/Expzip/Resources/joiner-x86.exe` へ自動で複写される。

    tools\joiner\build.cmd

要るもの: Visual Studio 2022 の C++ ワークロード (`cl.exe` と `link.exe`)。

## 決めごと

- **x86 でビルドする。** 32bit と 64bit のどちらの Windows でも動くため。x64 でビルドすると 32bit 環境で動かない
- **C ランタイムを使わない。** 使うと 100KB を超える。分割のたびに書き出すものとしては大きすぎる
- **署名しない。** 署名証明書を持たないため。SmartScreen の扱いは #60 のノートを参照
- 引数に `-q` を渡すと、メッセージを出さずに終了コードだけを返す (0 = 成功、1 = 失敗)

## 末尾に書き足す情報

Expzip はこの実行ファイルの後ろに、元の名前と照合用の値を書き足してから配る。

    [ 実行ファイル本体 ][ 元の名前 (UTF-16LE) ][ 32バイトの固定部 ]

固定部の中身 (すべてリトルエンディアン)。

| 位置 | 大きさ | 内容 |
|---|---|---|
| 0 | 8 | `EXPZSPLT` |
| 8 | 4 | 版 (1) |
| 12 | 4 | 断片の数 |
| 16 | 8 | 元のファイルの大きさ |
| 24 | 4 | 元のファイルの CRC32 |
| 28 | 4 | 元の名前の長さ (UTF-16 の文字数) |

名前を固定部より前に置いてあるのは、長さが変わるため。連結プログラムは末尾から
32 バイトを読んで印を確かめ、そこに書かれた長さのぶんだけ手前へ戻って名前を読む。
